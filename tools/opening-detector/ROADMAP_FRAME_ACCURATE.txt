0. OBJECTIF
--------------------------------------------------------------------------------
Pour TOUS les lecteurs (sibnet, sendvid, megaplay, vidmoly, vidmoly-va), détecter
le DÉBUT et la FIN de l'OP et de l'ED avec une précision FRAME-ACCURATE
(±1 frame ≈ 42 ms à 23,976 fps), rapportée en ms, en s'appuyant sur les
références CREDITED d'AnimeThemes (mêmes crédits que l'épisode → appariement image
quasi bit-exact).

Décisions cadrées avec l'utilisateur :
  - Précision : frame-accurate (±42 ms), pas de sub-frame/onset audio.
  - Portée : reconstruction de la FONDATION, pas des patches.
  - L'IMAGE credited = autorité UNIQUE du bord (elle mesure la coupe visuelle,
    le bon événement). L'audio = repérage grossier + choix de version SEULEMENT.
    (L'audio est plus fin ~12 ms mais mesure la musique, pas la coupe visuelle.)


--------------------------------------------------------------------------------
1. POURQUOI (cause racine des échecs observés)
--------------------------------------------------------------------------------
Les bugs megaplay (ED 21:10 au lieu de 21:15) et vidmoly-va (OP 3:28 au lieu de
3:11) venaient TOUS d'une fondation timestamp fragile :
  - decode -sseof séparés pour audio et vidéo → pts fenêtre-relatifs qui dérivent
    (10 s d'écart A/V sur megaplay dans la MÊME fenêtre).
  - ancre -sseof nominale (suppose 180 s décodées ; le seek keyframe débordait à
    175 s → 5 s d'erreur).
  - cascade d'heuristiques qui se contredisent (audio/credited/video override,
    fenêtre élargie sélectionnée au "fill" → vidmoly-va +15 s faux alignement).

FAIT MESURÉ (la clé) : en décodant avec -copyts + -ss ABSOLU (durée probée), audio
ET vidéo portent le MÊME pts absolu (megaplay : vidéo 1260.0, audio 1260.08). Le
"décalage A/V de 10 s" était un artefact de -sseof, pas un vrai désync.
=> une horloge absolue partagée par hôte supprime la classe de bugs à la racine.

3. FAIT — Stage 3 : précision frame-accurate du theme_t0 (CLOS 2026-07-15)
--------------------------------------------------------------------------------
RÉSULTAT : theme_t0 frame-accurate par hôte, avec un signal de confiance propre.
  megaplay t0=1275.114  vidmoly t0=1275.114  (IDENTIQUES au ms)  sibnet t0=1274.956
  consensus 73-82 % des landmarks à ±1 frame du mode. Reproductible (run à froid
  == run sur cache). Le 228 ms cross-host restant = sibnet (contenu/encode ED
  réellement décalé), PAS une erreur (cf. §3b : métrique = cohérence PAR HÔTE).

CAUSE RACINE trouvée : ce n'était PAS l'acceptation, c'était l'ESTIMATEUR + la
FOURNITURE de landmarks.
  1) pick_landmarks plafonnait à ~8 landmarks (min_gap_floor_s=8 sur clip 90s) et
     admettait des faibles (unique~6 bits sur cet ED très plat) → 3/8 acceptés,
     médiane bruitée. FIX : min_unique=10 (plancher de distinctivité) + gap floor
     3 s → ~19 landmarks forts (unique 10-23). k=24 plafond.
  2) La "spread" brute (84-668 ms) était un LEURRE : les estimations forment un
     MODE net sur la grille frame native (23.976fps) avec quelques outliers à
     ±N frames entiers (un landmark relocalisé sur la frame GOP voisine). La
     médiane simple était tirée par ces outliers. FIX : anchor_by_landmarks snappe
     à la grille frame, prend le MODE, moyenne SEULEMENT les estimations à ±1 frame
     du mode, et rapporte consensus_frac comme confiance. C'est ça qui rend
     theme_t0 frame-accurate.

CODE (oped/video_fingerprint.py) :
  - pick_landmarks : params min_unique (LANDMARK_MIN_UNIQUE=10), min_gap_floor_s
    (LANDMARK_GAP_FLOOR_S=3.0), k défaut LANDMARK_K=24.
  - anchor_by_landmarks : estimateur mode-consensus (FRAME_S=1001/24000,
    LANDMARK_CONSENSUS_FRAMES=1). LandmarkAnchor gagne n_consensus + consensus_frac.
  - proto_native.py mis à jour pour utiliser anchor_by_landmarks. proto_native2.py
    = harnais de sweep (floor/min_unique/hamming/sep + MAD-trim) ayant servi à
    trouver l'estimateur ; caches _native_ed__<host>.npz pour re-runs instantanés.

RETENUS pour Stage 4 (métrique + rappels, toujours valides) :
  - refine_edge_credited_video "start" ne peut que confirmer/pousser APRÈS theme_t0
    (frames avant = "invalid", pas "non-match"). => précision du DÉBUT = précision
    de theme_t0 (maintenant frame-accurate). Pas de détection de transition côté start.
  - ref_dur EXACT = 2157 frames à 24000/1001 = 89.972 s (PAS 89.5 = max VREF 2fps).
    Le clip credited EST l'ED diffusé => FIN = theme_t0 + ref_dur (frame-accurate).
    refine "end" reste utile pour les ED TRIMÉS (débuguer le None : fenêtre ref/
    épisode natives + ref_dur) — à faire dans Stage 4.C.
  - Les landmarks DOIVENT venir d'un décodage NATIF de la ref credited (r_time
    frame-exact) ; les r_time du VREF 2fps sont quantifiés 0.5 s => biais.
    ⚠ theme_bank.build_references appelle encore pick_landmarks sur un vfp 2fps
    (SAMPLE_FPS) — À CÂBLER en natif dans Stage 4 (ref décodée fps=None).
  - Métrique de vérité : cross-host from_end n'est PAS fiable (contenu POST-ED
